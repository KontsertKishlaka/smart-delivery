# Техническое задание

## 1. Общие сведения

- **Полное наименование системы:** `SmartDelivery` - система управления доставкой еды из ресторанов;
- **Краткое наименование:** `smart-delivery`;
- **Заказчик:** `ООО "ТехноФуд"` - оператор агрегационной платформы доставки еды.

## 2. Назначение системы

SmartDelivery предназначена для автоматизации процессов приема, обработки и исполнения заказов на доставку готовой еды из ресторанов. Система объединяет клиентов (через Telegram-бота) и операторов (через веб-панель).

## 3. Цели создания системы

- Уменьшить время обработки заказа и повысить точность;
- Обеспечить многоканальный прием заказов: Telegram-бот для клиентов, веб-панель для операторов;
- Автоматизировать передачу закрытых заказов в бухгалтерскую систему (1С) через REST API;
- Разработать систему в рамках MSA, ориентируя сервисы на Python и Go.

## 4. Область применения

Система охватывает следующие бизнес-процессы:

- Регистрация и управление ресторанами-партнерами и их меню (CRUD);
- Прием заказов от конечных клиентов через Telegram-бота;
- Обработка заказов оператором в веб-панели (просмотр, изменение статуса);
- Отправка клиенту уведомлений об изменении статуса заказа;
- Формирование отчетов (список заказов с фильтрацией, сумма заказов за период);
- Выгрузка завершенных заказов в 1С.

## 5. Функциональные требования

### 5.1. Модуль "Клиентский канал" (Telegram-бот)

| ID     | Название / Описание                                                                    |
| ------ | -------------------------------------------------------------------------------------- |
| TG-001 | Регистрация клиента по номеру телефона (кнопка "Отправить номер"), код не требуется    |
| TG-002 | Просмотр списка доступных ресторанов                                                   |
| TG-003 | Просмотр меню ресторана (название, цена, фото по ссылке)                               |
| TG-004 | Сборка корзины и оформление заказа (указание адреса доставки текстом)                  |
| TG-005 | Отправка геолокации (опционально, для уточнения адреса) через кнопку Telegram          |
| TG-006 | Получение уведомлений о статусе заказа (принят, готовится, передан курьеру, доставлен) |
| TG-007 | Возможность задать вопрос в свободной форме - ответ оператора вручную                  |

### 5.2. Модуль "Панель оператора" (Vue 3 + Vuetify)

| ID     | Название / Описание                                                                |
| ------ | ---------------------------------------------------------------------------------- |
| OP-001 | Авторизация по email и паролю (сессия на основе cookie)                            |
| OP-002 | Создание заказа вручную (по звонку клиента): выбор ресторана, блюд, адрес доставки |
| OP-003 | Просмотр активных заказов с фильтрацией по статусу, ресторану, дате                |
| OP-004 | Карточка заказа: детали заказа, кнопки смены статуса, история изменений            |
| OP-005 | Карта со статическими метками ресторана и клиента (OpenStreetMap)                  |
| OP-006 | История заказов и отчеты: список с пагинацией, просмотр суммы заказов за период    |
| OP-007 | Управление справочниками (CRUD): рестораны, меню (блюда, цена, фото)               |

**Технологии фронтенда:** Vue 3, Vuetify (или Vuetify 3), Vue Router, Vuex 4, Vue i18n (поддержка русского и английского языков), Axios для HTTP-запросов к API Gateway.

### 5.3. Модуль "Интеграция с 1С" (учебный стенд)

| ID     | Название / Описание                                                                |
| ------ | ---------------------------------------------------------------------------------- |
| C1-001 | Формирование JSON-пакета заказов со статусом "Доставлен"                           |
| C1-002 | Отправка пакета на REST-эндпоинт учебного стенда 1С с HTTP Basic Auth              |
| C1-003 | Логирование успешных и неуспешных попыток в БД (таблица export_log)                |
| C1-004 | Автоматическая отправка при накоплении 10 заказов или по кнопке в панели оператора |

> Примечание: на учебном стенде 1С реализуется простой HTTP-сервис, который принимает JSON и создаёт документ "Реализация товаров и услуг".

### 5.4. Модуль "Уведомления"

| ID      | Название / Описание                                                              |
| ------- | -------------------------------------------------------------------------------- |
| NOT-001 | При изменении статуса заказа отправлять клиенту сообщение через Telegram Bot API |
| NOT-002 | Шаблоны сообщений хранятся в конфигурации                                        |

### 5.5. Нетехнические требования

- **Backend Python**: FastAPI, SQLAlchemy (async), Alembic, Pydantic;
- **Backend Go**: net/http, стандартная библиотека, PostgreSQL driver;
- **Frontend (админка)**: Vue, Vuetify, Vue Router, Vuex 4, Vue i18n, Axios;
- **База данных**: PostgreSQL (одна БД, но разные схемы для сервисов);
- **Контейнеризация**: Docker, docker-compose (один файл для локального запуска);
- **Документация API**: автогенерируемый Swagger (FastAPI). Для Go-сервиса - вручную описать или использовать go-swagger (опционально);
- **Производительность**: время ответа API - не более 300 мс для 95% запросов (без учета внешних вызовов);
- **Масштабируемость**: система должна выдерживать до 50 одновременно активных заказов (MVP);
- **Безопасность**:
  - Клиенты аутентифицируются по номеру телефона (без кода);
  - Операторы - по email/паролю, сессия через HTTP cookie;
  - Роли: только `client` и `operator`;
  - Чувствительные данные (пароли, API-ключи) хранятся в переменных окружения, `.env` не коммитится.
- **Надежность**: при ошибках внешних систем (учебный стенд 1С) - повторные попытки с экспоненциальной задержкой (до 3 раз);
- **Наблюдаемость**: логи в stdout в JSON-формате (для каждого сервиса). Без метрик и трейсинга;
- **Версионирование API**: через URL `/api/v1/...`;
- **Документация**: Confluence и Jira НЕ используются. Вся документация - в формате Markdown описана в [docs](../docs/) и `README.md`, диаграммы в формате PlantUML, код на GitHub.

## 7. Критерии приемки

- Клиент через Telegram-бота может зарегистрироваться, выбрать ресторан и блюда, оформить заказ, указав адрес, и получить подтверждение;
- Оператор авторизуется в веб-панели, видит список заказов, открывает карточку, меняет статус (например, с "Принят" на "Готовится", "Доставлен");
- Клиент получает уведомление о каждом изменении статуса в Telegram;
- Заказы со статусом "Доставлен" автоматически или вручную выгружаются на эндпоинт учебного стенда 1С; результат выгрузки логируется;
- В панели оператора доступна страница с отчетом: общая сумма заказов за выбранный период;
- Все сервисы запускаются одной командой `docker-compose up`;
- Код размещен на GitHub, есть `README.md` с инструкцией по запуску и архитектурной диаграммой.
